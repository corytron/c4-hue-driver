1. What this driver does

This driver connects one Philips Hue bridge to your Control4 system over your own home network; no cloud account is involved and nothing leaves the house. Each Hue light you choose becomes an ordinary Control4 light that you can switch, dim, colour and program like any other light in the project. Changes made in the Hue app or with Hue switches and dimmers show up in Control4 within a second or two, because the driver listens to the bridge's live event feed rather than asking it over and over. Hue scenes can become Control4 switches: turning one on recalls the scene, turning it off turns that Hue room or zone off. The driver never adds, renames, moves or removes a Control4 device on its own; every such change is a button you click in Composer, and the driver reports in plain words what it did.

2. How Hue maps onto Control4

Hue and Control4 organise a home differently. The table shows what each Hue construct becomes on the Control4 side, and the actions that create the link.

In HueIn Control4How
The Hue bridgeThe Hue Bridge deviceYou add it once and pair it (chapter 4). Everything else is created from its Actions tab.

A Hue fixture that contains several lights gives one Hue Light per light.

What has no counterpart

  • Hue rooms and zones as controllable devices. There is no "room light" device that dims a whole Hue room at once. Control4 rooms, Advanced Lighting Scenes and Hue Scene switches cover that; a Hue zone appears only in the room mappings and as the owner of its scenes.
  • Hue motion sensors, buttons, dimmers and switches are not represented. Pressing a Hue dimmer still shows its effect on the lights in Control4, because the lights report their state.
  • Entertainment areas (light sync with screens and music) are not touched.
  • Several bridges. One Hue Bridge device per project is supported.
  • Smart scenes (Hue's day-long scenes such as Natural light) are not listed; only ordinary scenes are.

3. Installation

What you need

  • A Control4 controller on OS 3.3.0 or newer, and Composer Pro.
  • A Philips Hue Bridge (the square version 2 bridge) or a Hue Bridge Pro, on the same network as the controller, with a fixed address (give it a DHCP reservation in your router; the driver does not search for a bridge that moved).
  • The three driver files: hue_bridge.c4z, hue_light.c4z and hue_scene.c4z from the same build. Their Driver Version numbers match when they belong together.

Adding the drivers to the project

  1. Copy the three files to the computer that runs Composer Pro.
  2. In Composer, open the Driver menu and choose Add or Update Driver or Agent…. The Select Driver or Agent… file dialog opens; select all three files at once (hold Ctrl while clicking) and open them. Composer answers with Update Succeeded: Drivers or agents were successfully added: hue_bridge.c4z, hue_light.c4z, hue_scene.c4z.

Composer's Driver menu with Add or Update Driver or Agent…, the one route used both for installing and for updating.

  1. In System Design, select the room that should hold the bridge. In the Items pane on the right, use the Search tab, type Hue Bridge (manufacturer Philips Hue) and double-click the result. One Hue Bridge device appears in the room.
  2. Do not add a Hue Light or a Hue Scene by hand. The bridge creates them, already linked and bound, when you use its actions. The two drivers only need to be in the project's driver list, which step 2 did.

The Hue Bridge in the System Design tree, in the room it was added to.

The first Properties page

Select the bridge and open its Properties tab. Before pairing the page reads like this:

  • Driver Version: the build number, for example 116.
  • Status: Enter the bridge IP address.
  • Event Stream: Not paired.
  • Lights: 0 imported; Scenes: 0 imported.
  • Attention: None; Room Mappings: None; use Map Rooms By Name.
  • Events Received: 0; Stream Timeout (s): 600; Stream Watchdog (s): 300.

The Hue Bridge Properties page of a paired bridge. Chapter 5 explains every row.

Updating to a newer build

Updates go through the same Driver » Add or Update Driver or Agent… menu with the new files. Composer answers Update Succeeded: Drivers or agents were successfully updated: hue_bridge.c4z, hue_light.c4z, hue_scene.c4z and pushes the new version to every existing device at once: the bridge and every Hue Light and Hue Scene show the new Driver Version within a minute, the bridge restarts and its event stream is back within seconds, and the pairing, the lights and the scenes are untouched.

Never delete the Hue Bridge device to update or "reset" it. The pairing with the bridge and the list of which device is which light live on that device. A deleted and re-added bridge starts empty: you would have to pair again and every Hue Light and Hue Scene would read Not bound to a Hue Bridge until bound and linked again by hand (chapter 8). Updating in place keeps everything.

If you ever need to reload the same version, right-click the bridge and choose Update Driver; Composer asks Versions are equal. Do you want to overwrite…? and reloads it on Yes. For anything newer, use the menu route above.

4. Pairing with the bridge

Step 1: find the bridge's address

Open the Hue app on your phone: Settings » My Hue system » tap the bridge. Its IP address is listed there, for example 192.168.1.50. Reserve that address for the bridge in your router if you have not done so; the driver has to be told by hand when the address changes.

Step 2: enter it in Composer

On the bridge's Properties page, type the address into Bridge IP Address, for example 192.168.1.50, and click the row's Set button. Status changes to Not paired: press the link button, then run Pair Bridge. If what you typed is not a valid address then the driver ignores it and Status keeps saying Enter the bridge IP address; correct the text and click Set again.

The Set button rule. Composer sends a changed property to the driver only when you click the Set button that appears beside the row (together with Cancel) the moment the value differs. Pressing Enter or clicking somewhere else leaves the new value in the grid only, and the grid later jumps back to the driver's value. This applies to every editable property in this manual: Bridge IP Address, Debug Mode, the two stream settings, and a scene's Recall As.

A property row after editing: the Set and Cancel buttons appear beside the value, and only Set hands the change to the driver.

Step 3: press the link button, then Pair Bridge

  1. Walk to the bridge and press the large round button on top (the link button). The bridge accepts a new pairing for about 30 seconds after the press.
  2. Within those 30 seconds, open the bridge's Actions tab in Composer and click Pair Bridge.
  3. Watch Status: it reads Pairing: contacting bridge, then Pairing: found BSB003 001788fffe123abc, requesting key (the model and the bridge's identifier; a square version 2 bridge reports BSB002), then Paired. Bridge ID and Bridge Model fill in.

If you clicked before pressing the button, or the 30 seconds had passed, then Status reads Press the link button on the bridge, then run Pair Bridge again; press the button and click Pair Bridge once more. If Status reads Enter the bridge IP address first, step 2 was skipped. If it reads Pairing failed: Bridge not reachable: …, the controller cannot reach that address: check the address in the Hue app and that bridge and controller are on the same network.

Right after Paired the driver opens the bridge's event feed. Event Stream shows Connecting, then Connected since 14:03:12, and from the first event onwards Connected since 14:03:12, 12 containers, last 14:03:40. Within a few seconds the driver has read the bridge's lights, rooms, zones and scenes:

  • Lights reads, for example, 47 on bridge, 0 imported, 47 new, 0 missing, 0 unbound, 0 deleted and Scenes 125 on bridge, 0 imported, 0 missing, 0 unbound, 0 deleted.
  • Attention lists the new lights: 47 new lights on the bridge: Bar Bottom [Kitchen] #80, Bar Left [Kitchen] #81, Bar Right [Kitchen] #82 +44 more (Add Light or Import All New Lights).
  • Room Mappings fills in, because the driver runs Map Rooms By Name once by itself the first time it sees the Hue rooms (chapter 6).

Nothing has been added to the project yet. Chapters 6 and 7 are the next steps.

Test Connection

Test Connection on the Actions tab asks the bridge one question and writes the answer to Status: briefly Testing: GET /clip/v2/resource/bridge via 192.168.1.50, then Test OK: HTTP 200 via 192.168.1.50 in 0 s, bridge 001788fffe123abc. Three failures are possible: Test failed: key rejected (HTTP 401). Re-pair with Pair Bridge (the bridge no longer accepts this pairing, see below), Test failed: bridge reports ID 001788fffe456def, expected 001788fffe123abc (a different bridge answers at that address) and Test failed: … with the network error (nothing answers). When not paired it says Not paired. The test leaves the normal connection alone.

Forget Pairing

Forget Pairing removes the stored pairing from the controller and stops the event feed. Status returns to Not paired: press the link button, then run Pair Bridge (the address is kept), Event Stream reads Stopped, Bridge ID, Bridge Model, Stream Address and Last Event are cleared and Events Received returns to 0. The Hue Light and Hue Scene devices stay in the project and keep their links; they simply stop following the bridge until you pair again. Pair with the same bridge and everything resumes. Use it before pairing with a different bridge, or when a Test Connection says the key was rejected.

When the bridge is offline

If the bridge is unplugged, rebooting or unreachable then Event Stream reads Disconnected: transfer error 28: …. Reconnecting in 1 s (the reason varies) and the driver retries with a growing pause, doubling up to 60 seconds between attempts. Hue Light and Hue Scene devices keep showing their last known state; a command you give meanwhile is kept as "the latest wanted value" for that light and retried with growing pauses until the bridge answers. As soon as the bridge is back, Event Stream reads Connected since … again and the driver refreshes the full state of every light and scene, so Control4 catches up with whatever happened while it was blind. You do nothing.

When the bridge's address changes

If the bridge receives a new address from the router then the feed drops and keeps failing: Event Stream cycles through Disconnected: …. Reconnecting in 60 s and Connecting, and Test Connection fails with a network error. Look up the new address in the Hue app, type it into Bridge IP Address and click Set. The pairing is kept, because it belongs to the bridge and not to the address: Status stays Paired and the feed reconnects within seconds. Then reserve the address in the router so it does not happen again.

6. Rooms first

Before importing anything, tell the driver which Control4 room each Hue room stands for. The mapping has one job: when a light or scene is created, it goes into the Control4 room its Hue room maps to, unless you pick a room yourself. The mapping never moves an existing device, and changing a mapping later changes only where future additions land. That is deliberate: Control4 offers no way for a driver to move a device, and a device you dragged somewhere on purpose should stay there.

The Room Mappings property

Room Mappings lists every Hue room, then every Hue zone (marked (zone)), each with an arrow to its Control4 room:

Dining → Dining; Kitchen → Kitchen; Office → (unmapped); Upstairs Hallway → (Control4 room gone); Bedside Lights (zone) → Master Bedroom; Mini Bar (zone) → (unmapped)

  • (unmapped): no Control4 room chosen yet. Lights in that Hue room are skipped by Import All New Lights and need a room picked in Add Light.
  • (Control4 room gone): the mapping points at a Control4 room that has since been deleted from the project. Attention says 1 room mapping points at a Control4 room that no longer exists: Upstairs Hallway (Set Room Mapping); fix it with Set Room Mapping.
  • A Hue room that was deleted in the Hue app but still has a mapping is listed last as Old Nursery (deleted in Hue) → Office; remove it with Set Room Mapping and (no mapping), or leave it, it does no harm.
  • None; use Map Rooms By Name: nothing is mapped yet.

The Room Mappings row: Hue rooms and zones on the left of each arrow, Control4 rooms, (unmapped) or (Control4 room gone) on the right. The long value is clipped in the row; widen the Properties pane to read all of it, or read the result of Map Rooms By Name in Last Action, which lists the same mappings.

Map Rooms By Name

Map Rooms By Name maps every Hue room or zone to the Control4 room with exactly the same name (capitals and spaces at the ends do not matter) and leaves everything else alone: it never changes a mapping that exists, and it skips a name that two Control4 rooms share. The driver runs it once by itself the first time it reads the bridge's rooms after installation; you can click it again whenever you have created or renamed rooms on either side. Last Action reports, for example:

Mapped 9: Dining → Dining, Foyer → Foyer, Kitchen → Kitchen, …; no Control4 room named: Basement Hallway, Upstairs Hallway, Bedside Lights (zone), Mini Bar (zone); ambiguous: Hallway (2 Control4 rooms are named Hallway)

and on a later click Nothing new to map; 9 already mapped (kept). If it reports Nothing mapped: no Hue rooms fetched yet (connect the event stream and try again), the bridge has not been read yet: wait for Event Stream to say Connected since.

Set Room Mapping

Set Room Mapping maps one Hue room or zone by hand, or removes a mapping. Its dialog has two rows:

  • Hue Room: every Hue room, then every zone, each shown with its current mapping, for example Kitchen → Kitchen, Upstairs Hallway → (unmapped), Bedside Lights (zone) → Master Bedroom. Pick the one to change.
  • Room: (no mapping) first, then every Control4 room as Floor / Room, for example Second / Hallway. Where two rooms share a name the room's number is appended so you can tell them apart.

The Set Room Mapping dialog with the Hue Room list open: rooms first, zones after them, each with its current mapping.

The same dialog with the Room list open: (no mapping) at the top, then the project's rooms as Floor / Room.

Example: pick Upstairs Hallway → (unmapped) and Second / Hallway, click OK. Last Action reads Mapped Upstairs Hallway → Hallway and Room Mappings updates. To remove a mapping, pick the Hue room and (no mapping): Removed the mapping for Mini Bar (zone). If you click OK without choosing, Last Action says Not mapped: pick a Hue room first or Not mapped: pick a Control4 room or (no mapping). Before the bridge has been read, the Hue Room list holds only (no Hue rooms fetched yet; connect the event stream).

Zones. A Hue zone can be mapped like a room. A light's default room always comes from its Hue room (a light belongs to exactly one room in Hue), so a zone mapping matters for scenes: Add Scene and Add All Scenes Of Room put a zone's scenes into the zone's mapped room. For example map Bedside Lights (zone) to the Master Bedroom, and its scenes land there.

Room Audit

Room Audit compares, for every imported light, the Control4 room it is in with the room its Hue room maps to, and writes the differences to Last Action as a to-do list:

2 of 23 are not in the room their Hue room maps to: Bar Left is in Living Room; Hue says Kitchen → drag it to Kitchen in Composer if you want it there; Desk Lamp is in Hall; Hue says Office → drag it to Office in Composer if you want it there

Nothing is moved for you; if you agree with a line, drag the device to that room in the System Design tree, then run the audit again and the line disappears. When everything agrees it reads All 1 linked lights in mapped Hue rooms are in the rooms their Hue rooms map to (the number is how many lights were checked). When no imported light is in a mapped Hue room it reads Nothing to audit: no linked light is in a mapped Hue room; before any mapping exists, No room mappings; use Map Rooms By Name or Set Room Mapping first. A line ending in mapped to a Control4 room that no longer exists (Set Room Mapping) means the mapping, not the light, needs fixing. Running the audit changes nothing, so it is also a harmless way to make the bridge refresh its Attention line (see 8.2).

Last Action after a Room Audit: one line per light that sits in a different Control4 room than its Hue room suggests. The driver only reports; you drag.

Why the driver never moves a device. Control4 gives drivers no way to move a device between rooms, and a move would also be the kind of surprise this driver avoids: you may well want a Hue light that Hue files under "Kitchen" to live in the Control4 room "Bar". The audit is there so you can decide, light by light.

7. Importing lights

Two actions create Hue Light devices. Both create each device already bound to the bridge, named as in the Hue app, with its capabilities (dimming, colour, colour temperature) set from what the bulb reports, and with its current state. Both refuse to create a second device for a light that already has one, so clicking twice is safe.

Import All New Lights

Import All New Lights adds every light on the bridge that has no device yet, one at a time (count on roughly a second per light), each into the Control4 room its Hue room maps to. Two kinds of light are skipped on purpose and named in the result: lights whose Hue room is not mapped (or that are in no Hue room), and lights whose device you deleted in Composer (chapter 8 explains why). Last Action reads, for example:

Added 2 new lights: Porch #53 to Patio (device 2051), Hall Lamp #54 to Hallway (device 2052); skipped 3 with no mapped room (Set Room Mapping or Add Light): Attic Lamp #60 (Hue room Attic not mapped), Workbench #61 (Hue room Garage not mapped), Spare Bulb #62 (no Hue room); skipped 1 deleted in Composer (Add Light re-creates one): Vanity 3 (deleted 2026-10-22)

When there is nothing to do it reads No new lights on the bridge (47 on bridge, 47 imported). While an import or a refresh is running, any other click is refused with Busy: importing; try again in a moment or Busy: resyncing; try again in a moment; wait a few seconds and click again.

Add Light

Add Light adds one light into a room you choose. Its dialog has two rows:

  • Light: every light on the bridge that has no device yet, as Name [Hue room] #number, for example Porch [Patio] #53. The number is the light's number on the bridge; it tells two lights of the same name apart. A light that looks like the replacement of a missing one is listed first with a hint, Porch [Patio] #53 (looks like Porch #12, device 2051; re-link?); lights whose device you deleted in Composer come last, as Vanity 3 [Master Bathroom] #92 (deleted from Composer 2026-10-22). When every light is imported the list holds only (every light on the bridge is imported); before the bridge has been read, (no lights fetched yet; connect the event stream).
  • Room: (mapped room) first, then every Control4 room as Floor / Room, for example First Floor / Kitchen. Pick (mapped room), like any other entry, to use the Room Mappings entry of the light's Hue room; pick a room to put the light there regardless of the mapping.

The Add Light dialog with the Light list open: each entry is Name [Hue room] #number; lights deleted from Composer are listed last with the date.

The same dialog with the Room list open: (mapped room) first, then Floor / Room rows.

Click OK. Last Action reads Added Left Bedside Light #46 to Master Bedroom (device 1142) and the device appears in that room in the System Design tree within a second. If you pick (mapped room) for a light whose Hue room is not mapped then nothing is created and Last Action explains: Not added: Porch #53: Hue room Patio not mapped; pick a room, or Set Room Mapping first; pick a room explicitly, or map the Hue room first. A light that already has a device is refused with Not added: Porch #53 is already imported (device 2051); an empty choice with Not added: pick a light first.

The dialog remembers. Composer pre-fills the Add Light dialog with the choices from your last click on that action. When you add several lights in a row, check both rows every time: re-open the Light list and choose the next light, and look at Room, picking (mapped room) again whenever you want the mapping rather than the room you chose last time.

Where the device lands and what it is called

The new device goes into the room you picked (or the mapped room) and takes the light's name from the Hue app, for example Left Bedside Light. From that moment the Composer name is yours: rename it as you like, and move it to another room as you like; neither touches the link to the Hue light. If the Hue name changes later, Attention will mention it (chapter 8), nothing more.

The new light's Properties

Select a Hue Light device and open its Properties tab:

  • Status: Left Bedside Light (Hue color lamp), the Hue name and the bulb's model.
  • Hue Light ID: #46 (e0e51794…), the light's number on the bridge and the start of its long identifier.
  • Hue Name: Left Bedside Light; Model: Hue color lamp; Hue Room: Master Bedroom (blank for a light in no Hue room).
  • Online: Online when the bridge can reach the bulb, Offline when it cannot (the bulb has no power, or the device is not linked), blank while the bridge has not yet said either way.
  • Last Action: the result of the device's own two actions (chapter 10).

The Properties page of a Hue Light (Left Bedside Light): Status, Hue Light ID, Hue Name, Model, Online and Hue Room are filled in by the bridge.

Its Connections view shows the light's Hue Bridge input already connected to the bridge's Hue Lights output; you never have to make that connection for a device the bridge created.

Living with the imported lights on Navigators

Each Hue Light appears on its room's Lighting page. Tap the tile for on and off; the slider sets brightness, and the bulb responds within about a second. The slider settles on the level Hue reports back, in whole percents. A level of 0 % turns the bulb off and any level turns it on. On a colour bulb the Navigator offers both a colour wheel and a colour temperature control; on a white ambiance bulb only the temperature control; on a white-only bulb neither. The temperature range is the bulb's own, typically about 2000 to 6500 K. A colour chosen while the bulb is off is kept and applied when it next turns on.

8. Living with it: renames, replacements, deletions

Over the years bulbs get replaced, names change on one side or the other, devices get deleted by mistake and bridges get reset. This chapter walks through each case. The rule behind all of them: the Control4 device is the thing your programming refers to, so the driver keeps devices and re-points their links instead of deleting and re-creating, and it does nothing on its own that would make a later fix harder. What needs you is listed in Attention until you deal with it; nothing is lost by waiting.

8.1 Two-way state

Turn a light on in the Hue app, press a Hue dimmer, or let a Hue automation run: the Control4 light follows within one to two seconds (the bridge bundles its reports to one per second), and Events Received on the bridge ticks up. The other way round, a tap in Control4 reaches the bulb within about a second and the tile then shows the level Hue confirms. If you switch a bulb off at its wall switch (cutting its power) then Hue needs a while, sometimes minutes, to notice; the device's Online then reads Offline and Control4 is told the device is offline. When power returns the bulb comes back on its own and Online returns to Online. A light offline for more than a day is mentioned in Attention: 1 light offline for more than 24 h: Porch #53.

8.2 A light renamed in Hue, or a device renamed in Composer

Names are never changed behind your back on either side. When the Hue name and the Composer name of a device differ, Attention says so, but not right away: the line is refreshed at the bridge's next full read of the bridge (the event feed reconnects every few minutes when the house is quiet, see Stream Watchdog (s)) or as soon as you run any action on the bridge's Actions tab; Room Audit is a harmless one to click for that. Then it reads, for a device renamed in Composer from Left Bedside Light to Left Bedside Lamp:

1 Hue name differs from the Composer names: Left Bedside Lamp is Left Bedside Light in Hue (Adopt Hue Names or Accept Names As They Are)

(With several differences it reads 2 Hue names differ from the Composer names: ….) You have three ways to answer:

  • Adopt Hue Names renames every differing device in Composer to its Hue name; Last Action reads Renamed 1 device: Left Bedside Lamp → Left Bedside Light (device 1142) | Scenes: No Composer names differ from the Hue scene names, or No Composer names differ from the Hue names when there is nothing to do.
  • Accept Names As They Are keeps the Composer names and stops Attention from mentioning these particular differences: Accepted 1 name difference: Left Bedside Lamp (Hue: Left Bedside Light). A later change of either name is reported again.
  • Adopt Hue Name on one Hue Light device (its own Actions tab) renames just that device: its Last Action reads Renamed device 1142 to Left Bedside Light.

Scene devices join in: Adopt Hue Names, Accept Names As They Are and Link Devices apply to lights and scenes alike, so their Last Action always has two halves separated by | Scenes: , the lights' result first and the scenes' result after it, for example No Composer names differ from the Hue names | Scenes: Renamed 1 scene device: Read → Bedside Lights Read (device 1141). The driver never renames anything in Hue.

The Attention row after a device was renamed in Composer: 1 Hue name differs from the Composer names: …, naming both names and the two actions that resolve it.

8.3 A bulb replaced or deleted in Hue

If a bulb is deleted from the bridge in the Hue app, or replaced by a new one (which Hue treats as a new light), then its Hue Light device stays in the project and reads Status Gone from the Hue bridge since 2026-10-22 09:15; re-link or Forget with Online Offline; its tile no longer does anything, the bridge's Lights counts it as 1 missing and Attention reads 1 light missing from the bridge: Porch #12 (device 2051, since 2026-10-22) (Re-link Device To Light or Forget Light). Programming, Advanced Lighting Scenes and Navigator pages still refer to the device, so nothing of yours is lost.

When the replacement bulb has been added in the Hue app it shows up as a new light, and the driver notices that it looks like the missing one (same radio hardware, or the same name): 1 new light on the bridge: Porch [Patio] #53 (looks like Porch #12, device 2051; re-link?) (Add Light or Import All New Lights). Do not add it as a new device; re-point the old one:

  1. Open Re-link Device To Light. In Device, pick the gone device: Porch (device 2051, gone since 10-22). In Light, which lists every light that has no device at the moment (likely replacements first with their hint, lights whose device you deleted in Composer last), pick the replacement.
  2. Click OK. Last Action reads Re-linked device 2051 (was Porch #12) to Porch [Patio] #53. The device keeps its name, room, bindings and programming; its Status, Hue Light ID and capabilities now describe the new bulb and its tile works again.

The Re-link Device To Light dialog with its Device list open: devices whose light is gone or whose connection was removed, as Name (device id, gone since date). When there is none, the list holds only (no gone or unbound devices), as here.

The same dialog with its Light list open: every light that has no device at the moment, including lights whose device was deleted from Composer, marked with the date.

If the light comes back under its old identity (for example you restored a Hue backup) then the driver notices and the device is simply linked again; you do nothing. If the bulb is gone for good and you do not want the device either, use Forget Light (8.5) and then delete the device in Composer. A gone device is never dropped by the driver itself. If you pick a light that already has a device, Last Action says Not re-linked: Porch #53 is already linked to device 2060; the Device list says (no gone or unbound devices) when there is nothing to re-link.

8.4 A device deleted in Composer

If you delete a Hue Light device in Composer then the bridge is told at once: Lights ends in …, 1 deleted (after deleting most of them it reads, for example, 47 on bridge, 1 imported, 0 new, 0 missing, 0 unbound, 46 deleted) and Attention stays None, because deleting in Composer is a deliberate act. The driver remembers the deletion:

  • Import All New Lights skips that light on purpose and says so: skipped 1 deleted in Composer (Add Light re-creates one): Bar Left (deleted 2026-10-22). A bulk import will therefore never quietly bring back a device you removed.
  • Add Light lists it at the end of its Light list as Bar Left [Kitchen] #58 (deleted from Composer 2026-10-22). Picking it creates a fresh device (a new device for Control4, so programming that pointed at the old one has to be redone) and clears the memory of the deletion.

If you deleted a device while the controller was off or the driver was not running then the driver finds out at its next start and treats it the same way.

8.5 Forget Light

Forget Light is the deliberate way to release a device from its Hue light without deleting anything. Its Device list holds every managed device as Vanity 3 #92 (device 1130) (a gone or unbound one is marked so). On OK, Last Action reads Forgot Vanity 3 #92 (device 1130): unbound and left in the project for you to delete; the Hue light is listed under Add Light again. The device stays in the project with Status Forgotten by the bridge (was Hue light Vanity 3 #92). Delete this device in Composer, or bind it again and use Link Devices, its connection to the bridge removed and its tile dead; delete it in Composer when you are ready. The Hue light is available in Add Light and counted as new again. The same can be started from the device itself with its Forget This Light action. Compared with deleting a device straight away: Forget makes the light importable again, while a plain delete keeps it out of bulk imports.

The Forget Light dialog: every managed device as Name #number (device id).

8.6 Link Devices and the bare "Hue Light"

Occasionally a Hue Light device exists that the bridge does not manage: one added by hand from the Items pane, one that was Forgotten and that you want back, or every light after the bridge device itself was deleted and re-added (which this manual tells you never to do). Such a device reads Status Not bound to a Hue Bridge. The way in is a connection plus one click:

  1. Select the device, open its Connections view and connect its Hue Bridge input to the bridge's Hue Lights output (drag the bridge onto the input row). The device now reads Bound; waiting for the bridge.
  2. On the bridge, click Link Devices. For every bound device the bridge does not manage it tries two things: if the device remembers which Hue light it was (a Forgotten device does), it is linked to that light again; otherwise it is matched by name to a Hue light that has no device yet, and the name must be exactly the same and unique. Last Action reads Linked 1 device: Vanity 3 (device 1034) to Vanity 3 [Master Bathroom] #92 by name (or … by its rid for a remembered identity), All 47 bound devices are registered when there was nothing to do, or No devices are bound to this bridge.

If the name matches nothing then Last Action reads not linked 1: Hue Light (device 1034): no unimported Hue light has that name; rename the device in Composer to the Hue light's exact name and run Link Devices again: rename the device in the tree to the exact Hue name and click again. If two Hue lights share that name, … 2 unimported Hue lights have that name; rename the device in Composer to one Hue light's exact name … (rename one of them in the Hue app first). If two bound devices carry the same name, … 2 bound devices share that name; rename one in Composer and run Link Devices again. Linking never moves the device: it stays in whatever room it is in.

The Connections view of a Hue Light. In the upper list the device's row reads Hue Bridge | Control | HUE_BRIDGE | Input | Hue Bridge->Hue Lights: its Hue Bridge input is connected to the bridge's Hue Lights output. Devices the bridge creates come connected like this; a hand-added one is connected here by dragging the bridge from the lower list onto that row.

If you remove that connection on a managed device then the bridge counts it as 1 unbound, Attention reads 1 unbound device: Desk Lamp #12 (device 2043) (bind it to this bridge in Composer, or Forget Light) and the device reads Not bound to a Hue Bridge; connect it again and it resumes by itself, no click needed.

If two devices both claim the same Hue light (possible after copying devices around) then neither is changed and Attention reads 2 devices claim Hue light Desk Lamp #12: 2043 and 2051 (Forget Light on one of them): Forget one of the two and delete it.

8.7 The bridge offline and back

Covered in chapter 4: the driver reconnects by itself and refreshes everything when the bridge returns. Expect Event Stream to read Disconnected: …. Reconnecting in … s meanwhile; nothing is needed from you unless the bridge's address changed.

8.8 The bridge factory reset, restored or replaced

  • Factory reset. If the bridge is reset to factory settings then it forgets the pairing: Event Stream reads Disconnected: HTTP 401. Reconnecting in … s over and over and Test Connection says Test failed: key rejected (HTTP 401). Re-pair with Pair Bridge. Press the link button and click Pair Bridge; the lights and scenes you then add back in the Hue app come with new identities, so every Hue Light device reads Gone from the Hue bridge since … and you re-point each with Re-link Device To Light (the hints by name make this quick) and each scene device with Re-link Scene. Your Control4 programming survives.
  • Restore from a Hue backup. If the restore brings the same lights back under their old identities then the driver sees nothing wrong and links them again by itself. If some identities changed, those devices read Gone from the Hue bridge … and you re-link them as above. If the restored bridge no longer accepts the pairing, pair again.
  • A different bridge at the same address. If a replacement bridge answers at the old address then Test Connection reads Test failed: bridge reports ID 001788fffe456def, expected 001788fffe123abc. Click Forget Pairing, then Pair Bridge with the new bridge, then re-link the devices to their lights. Taking a replacement bridge over automatically is not supported in this version.

9. Scenes

A Hue scene is a saved look for one room or zone. The driver can show any scene as a Hue Scene device, a switch in a Control4 room: ON recalls the scene on the bridge, OFF turns the scene's Hue room or zone off, and the switch follows what happens in Hue. Hue creates about seven default scenes per room, so scenes are never imported automatically; you pick the ones you want.

The Scenes line

Before the first read it says 0 imported. Smart scenes are not counted.

When every scene is imported the list holds (every scene on the bridge is imported); before the bridge has been read, (no scenes fetched yet; connect the event stream).
  • Room: (mapped room) first, then Floor / Room, as in Add Light. Pick (mapped room), like any other entry, to use the Room Mappings entry of the scene's Hue room or zone.

The Add Scene dialog with the Scene list open: Room: Scene, zones marked (zone), dynamic scenes marked (dynamic).

What the switch does

  • ON (a tap on the tile, or programming turning it on) recalls the scene on the bridge, the way the Recall As property says. The member lights take the scene within about a second and the tile stays ON because the bridge reports the scene as active.
  • OFF turns the scene's whole Hue room or zone off, every light in it, imported or not, with one request to the bridge. The tile shows OFF.
  • The tile follows Hue. Recall the same scene from the Hue app or a Hue dimmer and the tile goes ON. Change any member light by hand (its own tile, the Hue app, a dimmer) or recall another scene in that room, and Hue marks the scene inactive, so the tile drops to OFF within a second. An ON tile therefore means "this scene is what the room is showing right now".
  • Scene devices have no slider: Control4 treats them as on/off switches.

The scene device's Properties

  • Status: Hue scene Nightlight in Bedside Lights (zone) (the scene and its Hue room or zone).
  • Hue Scene: Nightlight; Hue Room: Bedside Lights (zone); Hue Scene ID: #AbCdEf (0f3a2b1c…), the scene's short code and the start of its long identifier.
  • Recall As: how ON recalls the scene. As set in Hue (default) lets Hue decide: a scene marked dynamic plays its moving palette, any other is set once. Static always sets the scene once, a predictable look. Dynamic always plays the palette. Change it, click the row's Set button, and the next ON uses it.
  • Online: Online while the device is bound and its scene exists on the bridge, Offline otherwise.
  • Last Action: the result of the device's two actions.

Programming with scenes

To Control4 a Hue Scene device is a light. In programming, turn it on to recall the scene and off to turn the room or zone off; schedule it, put it behind a keypad button, or include it in an Advanced Lighting Scene next to other lights (the Hue lights themselves can be members of Advanced Lighting Scenes too). Its on/off state mirrors the bridge, so a Hue scene recalled from the Hue app is visible to Control4 as the switch being on.

Things that look wrong but are not

  • Event Stream shows a new "Connected since" time every five or ten minutes. The watchdog and the stream timeout reopen the feed on purpose; every reopening refreshes all state.
  • Lights shows "47 imported" with nothing else right after a restart. The bridge has not been read yet; the full line returns within seconds of Connected since.
  • Attention lists dozens of new lights after pairing. Those are the lights you have not imported yet. Import the ones you want and the rest stay listed; that is a reminder, not an error.
  • A property you changed jumped back. You did not click the row's Set button (chapter 4).
  • Room Mappings says "(deleted in Hue)" for every room right after a restart. Only until the first read of the bridge completes.

Diagnostics actions (normally not needed)

Test Connection asks the bridge one question over the normal connection and reports in Status (chapter 4). It is the first thing to click when lights do not respond: a Test OK means the controller reaches the bridge and the pairing is good.

Connect Event Stream and Disconnect Event Stream start and stop the live feed by hand. Disconnect leaves Event Stream at Stopped and the lights frozen at their last state until you connect again; the driver reconnects by itself at its next start in any case. Normally not needed.

Connection Test runs the developer's connection experiment against the Target you pick in its dialog, Bridge or Diagnostic Server (the latter needs the Diagnostic Server property and a test server the developer provides). It stops the live feed for about a minute, writes Connection test against bridge running; see Lua output and then a one-line verdict such as Connection test (bridge): stream OK, GET with stream open FAIL, concurrent 0/2, control OK to Status, and restarts the feed. Use it only when the developer asks for the result.

Reload Credentials checks that the stored pairing can be read back and reports in Status: Stored credentials readable and match memory is the good answer; No stored credentials means not paired; Stored credentials NOT readable although paired in memory; see Lua output would mean the controller's storage lost the pairing, in which case pair again. It never shows the key itself. Normally not needed.

Check CA Pinning confirms that the driver trusts only certificates issued for Hue bridges: it tries a public web site and expects to be refused. Pinning check passed: only Signify-signed certificates are trusted is the good answer; Pinning check inconclusive: … unreachable means the controller has no internet access at the moment, which is harmless for the driver. Normally not needed.

Debug Mode, Diagnostic Server, Dev Server and Stream Address are the developer's; leave them as they are unless asked.

12. Limits, and a quick reference of all actions

Limits and what is not supported

  • One Hue bridge per project. A second bridge is not supported.
  • Hue rooms and zones are not controllable devices; only lights and scenes are. Control4 rooms and Advanced Lighting Scenes take that role.
  • Hue motion sensors, buttons, dimmers and switches, entertainment areas and smart scenes are not represented.
  • The bridge is found by its address only. If the address changes you type the new one (chapter 4); a DHCP reservation avoids that.
  • Hue allows about ten light commands a second across everything that talks to the bridge. Dragging a slider quickly sends many requests; the driver keeps only the latest value per light and sends at most ten a second, so the bulb lags the slider slightly during fast moves and ends where the slider ends. A whole-room OFF through a scene switch counts as one request.
  • Changes from Hue reach Control4 within one to two seconds, never faster: the bridge bundles its reports once a second.
  • The driver never creates, renames, moves or deletes a Control4 device by itself. Importing, re-linking, forgetting, renaming and room mapping are all clicks; the only automatic housekeeping is the one-time Map Rooms By Name after installation and linking a device again when its light or its connection comes back.
  • Devices are never moved between rooms by the driver; Room Audit tells you what to drag.
  • Replacing the bridge itself is handled by pairing again and re-linking every device by hand.
  • Needs Control4 OS 3.3.0 or newer.

The two actions of a Hue Light

Adopt Hue NameRename this device in Composer to its Hue name.
Forget This LightAsk the bridge to release this device (same as the bridge's Forget Light).

The two actions of a Hue Scene

Adopt Hue NameRename this device in Composer to the scene's name (zone name in front for a zone scene).
Forget This SceneAsk the bridge to release this device (same as the bridge's Forget Scene).
