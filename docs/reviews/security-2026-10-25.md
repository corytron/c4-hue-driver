## Verdict

No high finding. The release packages carry none of the development surface
(checked on the artefact, below). The application key still reaches nothing
but the `hue-application-key` header. The decoy CA is a key-less certificate
whose only power is to make the driver fail closed. The shared lifecycle
(`bridge/owner.lua`) accepts exactly what the three copies accepted:
`registry.valid_rid` and `entry_for_command` are unchanged, and so are the
acceptance rules of hello, goodbye and forget. The keypad notifications carry
only range-checked numbers.

Three findings matter:

- **Finding 1.** The release `Test Connection` action sends the key outside
  the new request gate. That reopens 2026-10-24 finding 1 in the very states
  where Status says nothing is sent.
- **Finding 2.** A `not_pinned` TLS verdict is lifted by the next inconclusive
  check, while Status still says nothing is sent.
- **Finding 11.** The Release workflow hands its write token and Sigstore
  signing to unpinned third-party code.

In dev builds, signing closed the network path of 2026-10-24 finding 13. The
development handlers are still reachable from any driver in the project,
though, `Probe Call` included (finding 9). Findings 1 and 2 are a few lines
each in `driver.lua`, with one spec apiece.

- **The decoy is key-less.** `certs/decoy_ca.pem` holds one certificate and no
  key block: a self-signed ECDSA P-256 CA, "CN=c4-hue-driver decoy CA (trusts
  nothing)", with basicConstraints CA:TRUE, valid 2026-10-25 to 2056-10-17
  (SHA-256 fingerprint starting DB:82:9A:A4). Its public key differs from both
  Signify roots and from the dev diagnostic certificate. No private key was
  ever committed: `git log --all -S 'PRIVATE KEY'` finds only the spec's
  assertion. `tlscheck_spec.lua:139-161` pins one certificate, no key, and
  none of the Signify roots.
- **Why that matters only for availability.** The decoy is used for exactly
  one request, which carries no key, no header and no body
  (`tlscheck_spec.lua:67-72`). Whoever held its key could only produce a false
  `not_pinned`, which fails closed.
- **The verdict.** `http.certificate_failure` counts only curl 60 or 51 with
  no HTTP code (`http.lua:79-91`). `not_pinned` needs a completed HTTP
  exchange (`tlscheck.lua:64-66`).
- **Blocking a healthy controller.** A false `not_pinned` needs a TLS
  session or connection that the Signify bundle verified to be reused for the
  decoy request. On OS 3.4.2 the decoy was refused with curl 60 (design.md,
  hardware facts of 2026-10-25). Elsewhere [assumed]: libcurl compares the CA
  file before reusing either.
- **Ordering.** Apart from findings 1 and 2, no keyed request leaves before
  the verdict. `identity_ok` becomes true only in `tls_gate`'s callback
  (`driver.lua:728-731`). The keyed self-check waits for it (`:766-771`). The
  stream starts only from `choose_stream_address`'s callback, or from
  `Connect Event Stream` once `stream_ip` exists for the current address
  (`:1515-1524`). Every module request goes through `bridge_request`.
  Messages from devices before late init are queued, at most 200, and their
  replay sends no HTTP before the identity check.
- **Input from the bridge.** Resource ids are validated, names are sanitised
  in lists, and the SSE caps hold (findings 6 to 8 are robustness only).
- **The shared lifecycle.** The four intended behaviour changes of #56 (every
  waiting resync caller answered; a zone deleted while its AddDevice is
  pending marked gone; a field schema for zone lights; a stale field cleared)
  open nothing new.
- **Keypad settings.** `report_setting` (`device.lua:499-503`) sends
  `tostring(dev.setting(name))`, always a number, through the documented form
  of `SendToProxy` whose third argument is a string [verified: API
  25_proxy/_6-SendToProxy]. The notification names come from a fixed table,
  with `RATE` per the light_v2 reference (`HOLD_RATE_DOWN` and siblings). The
  bare value is a hardware finding (Composer rounds 41 and 42).
- **Keypad input.** Values from the proxy and from storage are range-checked
  (`device.lua:508-539`); NaN and infinity fail the comparisons and are
  refused. Button ids, actions and colours are parsed with `tonumber` and a
  6-hex pattern; nothing from the proxy is echoed unparsed.
- **The key stays out of logs.** `http.lua` logs the URL and body, never
  headers. `credentials.summary` prints the key's length only. `SendToDevice`
  to devices passes `logCommand` only with Debug Mode on [verified: API
  32_serial_network_device/_19-SendToDevice].
- **Workflows.** `permissions: {}` or `contents: read` at the top, and job
  permissions are the least needed except Release (finding 11). Every action
  is pinned by SHA. `actions/checkout` keeps no credentials. Inputs reach
  `run:` only through `env` and are regex-checked. Dependabot auto-merge runs
  on `pull_request`, not `pull_request_target`, and checks the PR author.
  `tools/setup-checks.sh` verifies the sha256 of the binaries it downloads.
- **`tools/deploy.py` and `labels_sync.py`.** `gh` is called with argument
  lists (no shell), and bodies go through stdin. Notes and briefs pass a
  private-data filter. Packages are checked against `SHA256SUMS.txt` and
  `manifest.json`, and `dev: true` is refused. Labels are never deleted.

## Residual risks accepted by design

- **Hostname verification is off for the bridge, and identity is a point in
  time.** The unkeyed identity check runs at start and at an address change.
  Later stream reconnects (backoff, watchdog, transfer timeout) and REST
  requests carry the key to whatever presents a Signify-issued certificate at
  the address. A peer holding a Signify certificate and its key (a rooted
  bridge) can also answer `/api/0/config` with the paired id. Neither C4:url
  nor `NetPortOptions` offers a peer-name option [verified: API
  35_url/_12-SetOption, 32_serial_network_device/_25-NetPortOptions], so the
  certificate's CN cannot be compared with the bridge id.
- **Padded address spellings.** The keyed self-check and the stream use
  padded spellings that the identity check never visited. They name the same
  address only as long as the controller's resolver reads them as numbers
  (verified on OS 3.4.2, design.md "Stream address rotation").
- **A stale feed after watchdog reconnects.** Under the abandoned-transfer
  cap, the feed may stay stale until the abandoned transfer's own timeout,
  which can be up to Stream Timeout (at most 86 400 s) (design.md
  "Concurrent transfers").
- **Inter-driver messages trust the project** (2026-10-24 finding 9).
- **Dev packages carry the dev key, and the Deploy HTTP server serves on
  every address while the Windows session downloads** (dev-loop.md). A cheap
  improvement: serve from a random directory name that only the brief names,
  or bind the VM's LAN address.
- **Private data in public files.** `.gitleaks.toml` and `tools/deploy.py`
  name the house subnet prefix and the bridge's vendor prefix in public
  files. The scanner needs them, and both are of low sensitivity (a common
  router default; a per-model OUI). The documents also name the controller OS
  and the bridge firmware build.
- **Dev loop:** reading on the LAN, rollback to an earlier signed bundle,
  withholding, and a spoofed server view (dev-loop.md "What is left").
